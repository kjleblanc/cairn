## What the contract now says

Two additions, no deletions, no rewording of anything already there.

In **Task records are memory**, after the paragraph about the log row's
columns and before the `DONE`/`STOPPED` paragraph:

> In an envelope-dispatched run, Cairn's runtime authors the report and log row
> itself, from its own verification plus the worker's claims.

The placement is deliberate. It sits after both record duties have been
described, so "the report and log row" has an antecedent, and its opening
clause scopes it: an AI working directly under this contract still owns step 6
unchanged. That mattered enough to state, because this repository's own tasks
are exactly that reader, and a sentence read as "Cairn writes the records now"
would have quietly excused every future task from writing its own.

In **The connected conductor**, after the paragraph that keeps each dispatch,
paid call, and concrete-risk action on its own approval:

> When a dispatched task finishes, the envelope itself writes the result card
> the owner sees, and the conductor then takes one short comment turn on it.
> That comment is a model call on the same cost basis as the rest of the
> conversation.

> Cairn may offer a push button when local commits are ahead of the remote;
> every push shows the exact target, effect, and recovery plan, and runs only
> on the owner's approval of that exact action.

The push paragraph grants nothing new. Publishing is already on the
concrete-risk list, and the sentence restates that list's own ceremony —
target, effect, recovery plan, approval of that exact action — so the affordance
is named without loosening the boundary it sits behind. It follows the
standing-authorization paragraph rather than replacing any of it: the
conductor's single standing authorization still covers conversation only.

## Limitations and remaining human judgment

- **Milestone movement: NO.** The milestone this phase was built to reach is a
  demonstrated conversation — request, pushback, dispatch, verified DONE, and
  the honest explanation — and nobody has run it. Every part it needs now
  exists and is tested, but the milestone is an achieved outcome, not a shipped
  capability, and the phase design puts the attempt after execution as an
  owner action. Repo task 055 is the precedent: its row said YES because the
  run actually happened, in a real project, with a commit id to point at.
  Writing YES here would add a stone to this project's cairn for a run that
  was never made, which is precisely the forged-DONE shape this whole phase
  spent six chunks closing off. The row says NO, and it should turn YES on the
  task that records the real attempt.
- A contract is text. This one now describes what the runtime does, and the
  code that does it was built and tested in repo tasks 058–078; nothing in this
  task re-proves any of it.
- The conductor-v1 eval row remains historical, as repo task 078 recorded. A
  v2 run costs real money and needs the owner's explicit go; none was made
  here.
- `cli/package-lock.json` is bumped but still describes dependencies the CLI no
  longer declares. Cleaning or deleting it is a separate decision, not a
  version-close edit.
