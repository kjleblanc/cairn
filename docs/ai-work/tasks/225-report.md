# Task 225 report - stop the portable patch applier at the permission boundary

**Lane:** A (the main checkout). **Base commit:** `1759f8e`.
**Brief claim commit:** `b4a0ad1`.

## Outcome

Task 225 is **STOPPED**. The offline selector/applier draft proved that the
requested writer cannot honestly be implemented with portable Node filesystem
operations while preserving Cairn's security posture.

The decisive problem is below the text layer. A same-directory temporary file
followed by `rename` replaces the original file's inode. Copying the ordinary
read/write/execute mode bits does not preserve or prove all of the original
file's security and filesystem metadata. Depending on the platform and
filesystem, the replacement may change the owner or group, POSIX ACLs,
extended attributes, capabilities, Windows owner/DACL/SACL/integrity labels,
EFS/compression state, or alternate data streams. Portable Node APIs cannot
completely enumerate, reproduce, compare-and-swap, and verify those families.

That is an application-permission/security boundary, not a harmless
implementation limitation. The project contract requires a pause and qualified
review before changing permissions, and the committed brief explicitly says
STOP when the result needs a native security claim. In-place truncation would
avoid replacing the inode but would violate the brief's crash-safety rule and
could leave partial bytes. Shelling out to a few platform utilities would
inspect only subsets and would not create one portable atomic guarantee.

The unsafe draft was therefore removed in full. The final tree contains no
Task 225 writer, selector, plan, receipt, transaction parser, failpoint, test
mutation seam, package-script change, App import, or route change. Task 224's
inert proposal protocol remains byte-for-byte unchanged and its focused tests
remain green. Activation remains empty and Q10 remains blocked.

## Limitations and next safe step

boundary, not another JavaScript rename wrapper. It must define the supported
platform/filesystem set and causally preserve or refuse owner/group,
permissions, ACLs, extended attributes, alternate streams, links/reparse
topology, and crash semantics. That work requires qualified application-
permission/security review before any real-project write is authorized.

A smaller read-only selector could be pursued separately, but it would not
unblock Q10 by itself and should not be presented as a patch applier.
